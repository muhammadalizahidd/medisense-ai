# Role permissions: phase 0 inventory

Status: draft for sign-off. Nothing is built. This is what the code enforces today, grouped into a proposed permission catalogue. The role columns show the **default** that will be seeded, after the decisions in section 6. Where a default differs from today's behaviour, the last column says "Today: ...".

Columns: **INT** Intake Officer, **SCH** Scheduler, **FIN** Finance, **FM** Finance Manager, **OPS** Operations Manager, **CL** Clinical Lead. The Super Admin is described in section 3. `Y` = allowed today, `-` = not allowed.

How it was produced: a scan of every role-name check in `src` (258 lines across 51 files), then reading each one. Menu and report tables were generated by running the real functions (`canOpen`, `scopeFor`), not copied by hand. "Enforced" means a server-side check; "menu only" means the page is hidden from the menu but the server does not check.

## 1. Two layers disagree today

| Layer | What it does | Strength |
|---|---|---|
| Menu (`pageAccess`) | Hides pages from roles that don't need them. | Cosmetic. Any admin who knows the URL opens the page. |
| Server checks | Role predicates inside about 20 modules. | Real, but only for the actions listed in section 2. |

Where the menu says "not for you" and the server has no check, the action is open to every admin. Section 4 lists these, and the default for them is decision 1 in section 6.

## 3. The Super Admin today

The Super Admin passes almost every check, but not all of them. Decision 2 is that the Super Admin has every permission with no exceptions, so these places change:

- Report clinical row-level detail needs Clinical Lead as well. Only "Director (clinical scope)" (Super Admin plus Clinical Lead, which is Neil) has it.
- Session finance view (`sessions.finance-verify`) excludes the Super Admin.
- Funding verification and the assistant's billing answers include the Super Admin but exclude Finance Manager.
- Several routing rules treat a Clinical Lead who is not the Super Admin as the dedicated lead (`workspace.ts`, `operations-engine.ts`, `operations-volume.ts`, `records.ts`, `assess.ts`).

## 4. Actions open to every admin today (no role check found)

These are server actions where the scan found no role-name check: referral processing (except triage), scheduling and quick booking, assigning a therapist, patient requests and patient invites, adding, deactivating and resetting therapists, exporting therapists, retrying failed automation runs, and the AI agent.

## 5. Inconsistencies found

1. **"Finance" means different things.** `funding.verify` was Finance only; `sessions.finance-verify` is Finance and Finance Manager; the assistant's billing answers are Finance (and Super Admin) only; `finance.work` is both. Decision 4 aligns funding. The assistant's billing answers will follow `finance.work`, so the Finance Manager gains them.
2. **Several roles get one view, not a union.** `records.ts accessFor()` returns the first match (clinical lead, then intake or ops, then scheduler, then finance), so Jo Marsh (Intake, Scheduler, Finance) sees only the intake summary. `sessions.ts viewOf()` does the same. A union of toggles would change this.
3. **Messages and code disagree.** "Only the scheduling team assigns therapists" is enforced as "any admin".

## 6. Decisions (confirmed)

1. **Actions open to every admin today:** defaults follow the menu. Each action defaults to the roles whose menu shows its page. Some admins lose actions they can technically do now, which is intended.
2. **Super Admin:** every permission, no exceptions. Clinical report detail and session finance view now pass for the Super Admin. Routing that prefers a dedicated Clinical Lead still looks at the role.
3. **Record and session views:** union. A person with several roles sees every summary their roles allow (Jo Marsh sees intake, scheduling and finance summaries, not just intake). How several views are laid out on one screen is a phase 4 design item.
4. **Finance Manager and funding:** FM gets `funding.verify` and `funding.edit` by default.

## 7. Always enforced (proposed, for sign-off)

Not role rules, so not toggles; shown on the screen as "Always enforced":

- Signed records change only by amendment; only the assessing or treating therapist signs, amends, checks in and records.
- Patients and families never see clinical notes, risks or recordings; recording is off by default.
- Psychology and trauma content stays with that discipline unless explicitly shared.
- Discharge needs outcomes and a signature; the 48-hour rule.
- An initiator cannot approve their own approval (except the Super Admin).
- Finance invoices carry no clinical narrative.
- AI never drafts the clinical Assessment field; every AI output needs a named human approval.
- Every create, edit, approve and permission change writes an audit entry; the audit trail cannot be edited.
- The Super Admin cannot be deactivated or have permissions removed; only a transfer moves it.
