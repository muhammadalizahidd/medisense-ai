# PDF documents: plan

Status: built for report exports, invoices and service agreements. The progress report has no print flow in the live product (only a static demo page), so it was left out. Charts were left out to keep the documents minimal. Goal: every PDF Medisense produces follows one designed format, built from reusable components, in the Navy rail colours with Inter.

## 1. What exists today

There is **no PDF library**. Every "PDF" is the browser's print dialog over an HTML page:

| Document | How it is made today | Where |
|---|---|---|
| Report export ("PDF summary") | A server-built HTML page with a **Save as PDF** button, opened in a new tab | `src/lib/live/report-files.ts`, route `src/app/api/care/reports/exports/[id]` |
| Invoice | "Download or print" calls `window.print()` over the invoice page | `src/features/live/invoice-detail.tsx` |
| Service agreement | "Use the browser's print to save a PDF" | `src/features/live/agreement-builder.tsx` |
| Progress report | `PrintButton` over the report page | `src/app/progress-reports/emily-carter`, `src/components/ui/print-button.tsx` |

Problems this causes: output depends on the viewer's browser, margins and headers vary, there are no page numbers or repeated table headers, the file can't be generated by the server (so a scheduled report can't attach a PDF), and the design doesn't match the platform.

## 2. Library: `@react-pdf/renderer`

Nothing is installed, so use **React PDF** as you suggested. It is component based, runs in Node route handlers, and supports React 19 in v4. `jsPDF` would mean drawing by coordinates, which defeats the component idea, and headless-browser PDF needs a browser binary that is heavy on Vercel.

Constraints to design around:
- Layout is flexbox only (no CSS grid, no CSS variables, no `rem`). Colours are literal values.
- Fonts must be registered as **TTF or WOFF files** (not WOFF2). Bundle Inter Regular, Medium, SemiBold and Bold as static files.
- It runs on the server only. Add `serverExternalPackages: ["@react-pdf/renderer"]` in `next.config.ts` and include the font files in the serverless trace.
- Output is not a tagged (accessible) PDF. Set the document title, author and language, and keep the CSV and Excel formats as the accessible alternatives.

## 3. Design: Navy rail, Inter

Taken from the `navy-rail` theme in `src/app/globals.css`, so the PDF looks like the platform.

| Role | Token | Value |
|---|---|---|
| Header band, table header | navy (sidebar) | `#172b36` |
| Muted text on navy | sidebar muted | `#9fb3bc` |
| Accent rules, key figures, links | accent | `#0d7a43` |
| Soft panels, zebra rows | mint | `#eef5f2`, `#f3f8f6` |
| Body text, secondary text | ink | `#1f2937`, `#4b5563` |
| Hairlines | border | `#e8eaeb` |
| Status | healthy / watch / at risk | `#0a6b3c`, `#a8480a`, `#c0271c` with their tints |

PDFs always use Navy rail, whatever appearance the viewer has chosen: a document that is emailed or filed should look the same everywhere.

```
┌──────────────────────────────────────────────────────────────┐
│ ▓▓ MEDISENSE   Clinical Operations              Report PDF  ▓▓│  navy band, white text
├──────────────────────────────────────────────────────────────┤
│ Referral volume                                              │  title, Inter SemiBold 22
│ 1 Nov – 30 Nov 2026 · Prepared for Neil Hensley · 14 Nov     │  one meta line
│ ┌ 128 ┐ ┌ 293 ┐ ┌ 82% ┐ ┌ $214k ┐                            │  summary tiles (mint)
│ ── Filters ─────────────────────────────────────────────     │
│ Period … Discipline … Funding …                              │  key–value grid
│ ── Report ──────────────────────────────────────────────     │
│  Week      Referrals   Supports                              │  navy table header
│  …                                                           │  zebra rows, header repeats
├──────────────────────────────────────────────────────────────┤
│ Snapshot as at 14 Nov 2026 12:00 pm AEST · Confidential  1/3 │  footer, page numbers
└──────────────────────────────────────────────────────────────┘
```

Rules: Inter only (400, 500, 600, 700); no gradients or shadows; accent green only for rules, key figures and links; status never by colour alone (always a text label); dates `Tue, 10 Nov`, times `10:30 am`, AUD, Australian English, "patient" not "client".

## 4. Component library

`src/lib/pdf/` (server only, no UI imports):

| File | Contents |
|---|---|
| `theme.ts` | The tokens above, type scale and spacing, as the one place hex values live in the PDF code |
| `fonts.ts` | Registers Inter from `src/assets/fonts/` |
| `components/page.tsx` | `DocPage`: navy header band, footer with page numbers (`render` prop), margins |
| `components/title.tsx` | `TitleBlock`: title, one meta line, optional status tag |
| `components/stats.tsx` | `StatTiles`: up to four number tiles with a change line |
| `components/section.tsx` | `Section`: heading with an accent rule |
| `components/meta.tsx` | `MetaGrid`: key–value pairs in two columns |
| `components/table.tsx` | `DataTable`: typed columns (text, number, money, percent, date), right-aligned numbers, zebra rows, **repeated header on every page**, "Suppressed" cells |
| `components/chart.tsx` | `BarChart`, `LineChart` as SVG, one series colour |
| `components/callout.tsx` | `Callout`: notes, precautions and the **AI draft** label, matching the platform's AI, rule and person layers |
| `components/signature.tsx` | `SignatureBlock`: name, role, date, for documents a person signs |
| `render.ts` | `renderPdf(element)` → `Buffer`, with title, author and language set |

Documents (`src/lib/pdf/documents/`): `report.tsx`, `invoice.tsx`, `agreement.tsx`, `progress-report.tsx`. Each takes a plain data object and composes the components above, so changing the look is a change to one component.

## 5. How it connects

- The existing export snapshot stays the source. The export route renders `ReportDocument` from the snapshot and returns `application/pdf` with `Content-Disposition`. The audit entry, expiry, revoke and rights check are unchanged.
- The format is renamed from "PDF summary" to **PDF**. Old stored exports keep working by mapping the old name.
- Scheduled reports can now attach a real PDF, because rendering no longer needs a browser.
- Invoice, agreement and progress report buttons call a server route that renders the document and returns the file, replacing `window.print()`. The "download recorded" audit step stays.
- The HTML "Save as PDF" page and `PrintButton` are removed once nothing uses them.

Phase 1 and 2 first: they give the shared look and replace the most visible PDF.

## 7. Testing

- **Render tests**: each document renders with sample data to a buffer that starts with `%PDF`, has the expected page count, and extracts the key text (title, a figure, the footer).
- **Theme parity test**: the tokens in `theme.ts` must equal the `navy-rail` values in `globals.css`, so the PDF can't drift from the platform.
- **Table tests**: a 500-row table paginates, repeats its header, and keeps suppressed cells as "Suppressed".
- **Visual check**: the preview script converts pages to images for review at A4, on a long table, an empty report, and a role that sees aggregate-only data.
- **Permissions**: the export rights, revoke and expiry tests stay as they are, and a test confirms a PDF never contains rows the viewer's role can't see.

## 8. Risks

- **Serverless**: the library adds weight and the fonts must be traced into the function. Check cold start and bundle size on a Vercel preview before phase 2 ships.
- **Long reports**: 500-row tables are rendered in one pass. If rendering is slow, cap PDF rows and point to CSV for the full data.
- **Text coverage**: Inter covers Latin, Greek and Cyrillic. A name in another script would need a fallback font.
- **Accessibility**: not tagged, as noted in section 2.

## 9. Decisions to confirm

1. **Scope of the first release**: reports only, or all four document types.
2. **Navy rail always**, rather than following the viewer's chosen appearance.
3. **Branding**: a text wordmark ("Medisense") in the header, since there is no logo file. Add a logo if you have one.
4. **Remove the print flows** once the PDFs are in, rather than keeping a fallback.
